# Rustic language and C-host contract

Rustic is a bounded Rust-*like* expression interpreter, not `rustc`. The public entry point is `runtime/include/rustic.h`; `runtime/rustic.c` owns parsing and evaluation. The strict-C99 [host driver](../tests/fixtures/rustic_expression_driver.c), [direct C API fixture](../tests/fixtures/rustic_api_contract_driver.c), [literal contract fixture](../tests/fixtures/rustic_integer_literal_contract.txt), [negative match contract fixture](../tests/fixtures/rustic_negative_match_patterns.txt) and [checked arithmetic fixture](../tests/fixtures/rustic_checked_arithmetic_contract.txt) are executable reference cases. Python is test/report tooling, not the interpreter.

## Accepted forms

- Decimal nonnegative integer literals up to the host C `LONG_MAX` and immediately adjacent negative decimals down to host `LONG_MIN`; unary `-` and `!`; `+`, `-`, `*`, `/`, `%`, parentheses, comparisons, and short-circuit `&&`/`||` (boolean integers `0`/`1`). Arithmetic precedence follows the parser's expression grammar; unary operators bind before multiplication. Exactly one comparison (`==`, `!=`, `<`, `<=`, `>`, `>=`) is accepted per unparenthesized comparison expression; `3 > 2 > 1` and `1 == 1 != 0` report `RUSTIC_ERR_EXPECTED_OPERATOR` / `expected operator`, including in skipped logical operands and unselected match arms. Use `(3 > 2) == 1` when intentionally comparing a boolean integer, or `1 < 2 && 2 < 3` for a range check. The [15-row comparison contract](../tests/fixtures/rustic_comparison_chain_contract.txt) covers accepted and rejected compositions.
- `let name = expr;`, assignment to an existing binding, semicolon-separated statements, scoped `{ ... }` blocks, `if condition { ... } else { ... }`, `while condition { ... }` with `break;`/`continue;`, and integer-pattern `match expr { -2 => expr, 0 => expr, _ => expr }`. Match patterns are decimal literals (optionally prefixed by an immediately adjacent `-`) or `_`; arms use commas. A pattern can reach host `LONG_MIN` via a signed decimal token, as can an immediately adjacent negative expression literal; neither is evaluated by negating a positive out-of-range magnitude. Patterns such as `- 2`, `-(2)` and `+2` are excluded. Skipped expression operands (including unselected match arms) consume expression grammar without evaluating values, but **skipped blocks** (including unselected `if`/`else` and `while` bodies) are scanned for balanced braces, not checked for valid statements: `if 0 { 1 + * } else { 7 }` returns `7`. Selected blocks do parse their statements. Match *patterns* are parsed and range-checked even after an earlier arm matches.
- An evaluated `match` allows at most one `_` wildcard arm and one occurrence of each numeric pattern. `match 0 { _ => 7, _ => 8 }` returns `RUSTIC_ERR_DUPLICATE_MATCH_DEFAULT` / `duplicate match default`; `match 0 { 0 => 7, 0 => 8 }` returns `RUSTIC_ERR_DUPLICATE_MATCH_PATTERN` / `duplicate match pattern`. Signed patterns compare by value, so `-0` and `0` are duplicates. Duplicate arms are errors even after an earlier arm matched; zero wildcards are allowed when an integer arm matches, and an unmatched match still returns `no matching match arm`. Each nested `match` has its own pattern set. Unselected arm expressions still consume grammar without executing side effects; duplicates are checked before parsing the duplicate arm expression. Whole matches skipped by logical short-circuiting and unreachable loop-body suffixes are only brace-scanned and do not validate uniqueness. See the [match-default contract](../tests/fixtures/rustic_match_default_contract.txt), [numeric-pattern contract](../tests/fixtures/rustic_duplicate_match_literal_contract.txt), and direct C API output-preservation fixture.
- Named `fn` declarations, recursive calls and function values; arrays of integer elements (`[1, 2]` or `[1, 2,]`) with checked `xs[index]`, plus selected bounded built-ins such as `len`, `push`, `map` and `fold`. Arrays and functions are runtime values but the public entry point returns only `long`—end a program with an integer expression. A single optional final comma is accepted after an array element, also by the grammar-only short-circuit parser; `[1,,]` remains invalid, and the 16-element array cap still applies. Calls with nonempty argument lists also accept one trailing comma (`add(2, 3,)`, `sum([1, 2,],)`), including in grammar-only skipped operands. Leading/doubled commas remain invalid; the comma does not count as an extra argument. Function *parameter declarations* do not gain trailing commas. See the [array comma contract](../tests/fixtures/rustic_array_trailing_comma_contract.txt), [call comma contract](../tests/fixtures/rustic_call_trailing_comma_contract.txt) and interpreter tests for callback and temporary lifetime behavior.
- An unbound array base remains live through its postfix index expression, even when that expression calls an allocating/compacting helper: `[9][len(push([0], 1))-2]` returns `9`. Bound, block-returned and function-returned array bases follow the same bounds/type rules; errors do not update the C API output. The [index lifetime contract](../tests/fixtures/rustic_index_base_lifetime_contract.txt) exercises these forms and invalid indices.
- Parameters within one `fn` declaration have distinct names: `fn pick(x, x) { x }; pick(1, 2)` reports `RUSTIC_ERR_DUPLICATE_PARAMETER` / `duplicate parameter` at declaration time rather than allowing the later argument to shadow the first. Outer bindings or parameters of different functions may reuse names. Trailing commas and missing parameters retain `expected identifier`, and call arity retains `wrong argument count`. A declaration inside a selected block is checked, whereas an unselected brace-scanned block is not checked for statements. See the [executable host contract](../tests/fixtures/rustic_function_parameter_contract.txt) and direct C API regression for unchanged output on error.
- Two `fn` declarations with the same name in one active lexical scope report `RUSTIC_ERR_DUPLICATE_FUNCTION` / `duplicate function`, rather than silently replacing the earlier named call target. An inner block or function body may declare a same-named function and shadows it only for that inner scope; after the scope exits, the outer function remains callable. Declaration syntax takes precedence (a missing `;` still reports `expected semicolon`), then duplicate detection precedes the 8-function capacity error. Different function names and `let` bindings retain their prior behavior. Unselected brace-scanned blocks do not validate duplicate declarations. The [11-row host contract](../tests/fixtures/rustic_duplicate_function_contract.txt), focused precedence tests and direct C API fixture cover errors, nested scope, output preservation and recovery.

Identifiers (binding names, function names, parameters, references and call targets) accept at most 63 characters. A longer name returns `RUSTIC_ERR_IDENTIFIER_TOO_LONG` / `identifier too long`, rather than aliasing its first 63 characters; even grammar-only skipped expression operands check this limit. Skipped brace-delimited bodies remain brace-scanned and may defer the diagnostic until selected/evaluated. The [identifier host contract](../tests/fixtures/rustic_identifier_length_contract.txt) covers the boundary, alias prevention and skipped operands.

## Embedding and failures
Adjacent evaluated statements need a separating `;`: `1 2`, `let x = 2; x = 3 4`, and `while 0 { 1 } 7` return `RUSTIC_ERR_EXPECTED_SEMICOLON` / `expected semicolon`, including inside a selected block. After `while`, this also covers unary `!`/`-` and array-literal `[` statement starts; `1 -2` remains binary subtraction and `xs[0]` remains indexing. `1; 2` succeeds; a final expression before `}` or end-of-input needs no semicolon. Unknown trailing punctuation such as `1 @ 2` still reports `RUSTIC_ERR_TRAILING_INPUT`. The [host contract](../tests/fixtures/rustic_missing_semicolon_contract.txt) exercises these paths; failed calls preserve the C API output.

The cursor scan of unreachable loop-body text after `break;` or `continue;` consumes one shared step per source byte, including text inside nested braces, selected `match` arm suffixes, unselected `if` branches and whitespace between them. A long suffix reports `RUSTIC_ERR_STEP_LIMIT_EXCEEDED` and leaves the C output unchanged; short suffixes remain unevaluated, and unbalanced braces still report `RUSTIC_ERR_EXPECTED_CLOSING_BRACE`. The [executable loop-exit contract](../tests/fixtures/rustic_loop_exit_scan_contract.txt) covers accepted and rejected forms. This scanner balances braces but does not parse the unreachable statements' grammar.

Each visited arm of an evaluated `match` (even after a previous arm matched) charges the shared 512-step budget. If it runs out, the API returns `RUSTIC_ERR_STEP_LIMIT_EXCEEDED` and does not change the output. A whole `match` expression skipped by `&&`/`||` still uses brace scanning; long arithmetic chains can also bypass this step budget. These are resource-behavior limits, not a security sandbox.

```c
#include "rustic.h"
long result = 0;
RusticStatus status = rustic_eval_expression("let x = 2 + 3; x * 4", &result);
/* status == RUSTIC_OK, result == 20 */
/* on failure, use rustic_status_message(status); do not use result */
```

Pass a NUL-terminated source and a non-NULL output pointer. Every call starts with fresh interpreter state. On success, `RUSTIC_OK` writes the final integer to `*out_value`. On failure, the output is **not updated** and the status describes the failure; `NULL` arguments return `RUSTIC_ERR_EXPECTED_INTEGER`. The host fixture prints `source => result` on success and `message: source` to stderr with exit code `2` on failure. The enum names and messages are in the [C header](../runtime/include/rustic.h) and implementation; do not infer a source position from a status code.

Decimal expression digits beyond `LONG_MAX` and nonnegative match patterns beyond `LONG_MAX` return `RUSTIC_ERR_INTEGER_OVERFLOW` / `integer overflow` rather than silently clamping; adjacent negative decimal expression tokens and signed match patterns below `LONG_MIN` do likewise. A directly adjacent negative expression literal can represent `LONG_MIN` (for example `-9223372036854775808` on a 64-bit-long host); `- (LONG_MAX+1)` with whitespace or `-(LONG_MAX+1)` with parentheses still fails positive literal conversion. Negating a *computed* `LONG_MIN` has the same overflow status. Grammar-only skipped operands consume the negative digits without range conversion, whereas match-arm patterns are checked even when an earlier arm matched. Evaluated `+`, binary `-` and `*` also reject a result outside the host C `long` range. `/` and `%` reject `LONG_MIN` with divisor `-1` with the same overflow status; a zero divisor still returns `RUSTIC_ERR_DIVISION_BY_ZERO`. In-range division truncates toward zero and the remainder follows the C99 signed-integer rule. `sum(array)` and `prefix_sum(array)` check every intermediate addition in input order; even a later negative element cannot rescue an overflowing prefix. `window_sum(array, n)` checks each addition in each evaluated sliding window in input order; a later negative element cannot rescue an overflowing window, including an overlapping window. `sum([])` returns `0`; `prefix_sum([])` and `window_sum([], 1)` return empty arrays. `moving_average_sum(array, n)` checks each evaluated window addition before dividing its in-range sum by positive `n` (C99 truncation toward zero); even a sum that would divide to an in-range mean fails if the intermediate addition overflows. Empty or short windows return empty arrays. `chunk_sum(array, n)` checks each addition in every evaluated fixed-size chunk, including a partial final chunk; overflowing an intermediate total fails even when a later element would cancel it. `chunk_sum([], n)` returns an empty array. `adjacent_diff(array)` copies the first element and checks every subsequent subtraction before evaluating it, returning the same overflow status at either host-long boundary; `adjacent_diff([])` returns an empty array. `variance_sum(array)` uses the truncated integer mean and checks every intermediate mean addition, element-minus-mean difference, square, and sum-of-squares addition against host `long`; even an overflowing mean prefix that could later cancel fails. It rejects empty arrays as before. For even-length arrays, `median(array)` checks the sum of the sorted middle pair before division, returning `RUSTIC_ERR_INTEGER_OVERFLOW` on an overflowing intermediate even if the mathematical midpoint would fit; in-range sums use C99 truncation toward zero. An odd-length array selects its middle element without addition; empty arrays remain errors. Other array/statistics built-in intermediate arithmetic outside the named helpers remains unchecked. An error leaves the C API output untouched. Skipped expression operands such as `0 && (LONG_MAX + 1)` are consumed without performing arithmetic; `0 && (1 + *)` still rejects malformed expression syntax, while skipped `{ ... }` blocks are only scanned for balanced braces and can contain malformed statements. See the [sum contract fixture](../tests/fixtures/rustic_sum_overflow_contract.txt), [prefix-sum contract fixture](../tests/fixtures/rustic_prefix_sum_overflow_contract.txt), [window-sum contract fixture](../tests/fixtures/rustic_window_sum_overflow_contract.txt) and [moving-average contract fixture](../tests/fixtures/rustic_moving_average_overflow_contract.txt) and [chunk-sum contract fixture](../tests/fixtures/rustic_chunk_sum_overflow_contract.txt) and [adjacent-diff contract fixture](../tests/fixtures/rustic_adjacent_diff_overflow_contract.txt) and [variance-sum contract fixture](../tests/fixtures/rustic_variance_sum_overflow_contract.txt) and [median midpoint contract fixture](../tests/fixtures/rustic_median_midpoint_contract.txt) for host-portable boundaries, composition, invalid arguments, cleanup and lazy branches.

`top_sum(array, n)` sorts values descending, selects up to `n` elements, and rejects an out-of-range host-`long` intermediate sum before addition; an overflowing prefix is rejected even if later selected values would cancel it. Empty arrays or zero selected elements return `0`; negative `n` and non-integer counts retain their existing diagnostics. See the portable [top-sum host contract](../tests/fixtures/rustic_top_sum_overflow_contract.txt). This guarantee covers `top_sum`'s selected additions only; the checked operations of other named helpers are documented above. Other array/statistics arithmetic remains unchecked.

`weighted_score(array, fn)` invokes its one-argument callback for each integer element and checks each returned integer addition against host `long` limits *before* computing it. An overflowing prefix is rejected even when a later callback could cancel it, with `RUSTIC_ERR_INTEGER_OVERFLOW` and unchanged C API output. Empty arrays return `0`; invalid callbacks and non-integer callback results retain their prior errors. See the portable [weighted-score host contract](../tests/fixtures/rustic_weighted_score_overflow_contract.txt). Other unlisted helper arithmetic remains unchecked.

`histogram_pairs_score(values, counts)` requires equal-length integer arrays and checks each signed multiplication *before* evaluating it, then each left-to-right score addition before signed overflow. A prefix that exceeds host `long` fails even if a later pair would cancel it; `([], [])` returns `0`. On error the C API output is unchanged. See the portable [histogram-pairs host contract](../tests/fixtures/rustic_histogram_pairs_overflow_contract.txt); other unlisted helper arithmetic remains unchecked.

`histogram_distance_score(values, counts, expected)` and `histogram_within_distance(values, counts, expected, limit)` require equal-length value/count arrays. For each value, they count occurrences in `expected`, take the absolute difference from its count, and sum left to right; expected elements with no listed value each add one. They check subtraction, `LONG_MIN` absolute value, every sum addition, and unseen-element increments *before* host-long overflow. An overflowing prefix fails with `RUSTIC_ERR_INTEGER_OVERFLOW` and unchanged C API output, including the predicate form even with a large limit. Empty arrays score zero. See the [distance host contract](../tests/fixtures/rustic_histogram_distance_overflow_contract.txt); other unlisted helper arithmetic remains unchecked.

`outlier_score(array, min, max)` sums the distances of elements below `min` or above `max`, checking each subtraction and nonnegative left-to-right sum before host-long overflow. When bounds are reversed, the existing below-`min` branch takes precedence; the bounds are not silently reordered. Overflow returns `RUSTIC_ERR_INTEGER_OVERFLOW` and leaves the C API output unchanged. Empty arrays score zero, unselected branches do not evaluate the helper, and existing type/arity diagnostics remain. See the [portable host contract](../tests/fixtures/rustic_outlier_score_overflow_contract.txt); other unlisted helper arithmetic remains unchecked.

## Runnable host examples

From the repository root (choose any writable output path):

```sh
cc -std=c99 -Wall -Wextra -Werror -Iruntime/include runtime/rustic.c tests/fixtures/rustic_expression_driver.c -o /tmp/rustic-demo
/tmp/rustic-demo 'let x = 2 + 3; x * 4'  # => 20
/tmp/rustic-demo '0 && 999999999999999999999999999999999999'  # => 0 (not evaluated)
/tmp/rustic-demo '999999999999999999999999999999999999'  # exit 2: integer overflow
/tmp/rustic-demo '9223372036854775807 + 1'  # exit 2: integer overflow on 64-bit long hosts
/tmp/rustic-demo 'match 0 { 999999999999999999999999999999 => 1, _ => 2 }'  # exit 2: integer overflow
/tmp/rustic-demo 'match -2 { -2 => 8, _ => 0 }'  # => 8
/tmp/rustic-demo 'let xs = [1, 2]; xs[2]'  # exit 2: array index out of bounds
```

The first oversized digits exceed `LONG_MAX` on normal 32/64-bit hosts; the checked arithmetic example uses a 64-bit boundary. The pytest fixtures construct exact boundaries from `sizeof(long)` for portability. A Docker-backed host run is in the [README](../README.md#run-with-docker).

## Resource boundaries and exclusions

The implementation caps identifiers at 63 characters, arrays at 16 elements and 64 live slots, named functions at 8, bindings at 1024, and evaluation at 512 steps. It also caps simultaneously active evaluated/grammar-only skipped expression factors at 64; nested unary operators, parentheses, calls, and selected branches that exceed this depth report `RUSTIC_ERR_STEP_LIMIT_EXCEEDED` / `step limit exceeded` rather than overflowing the C call stack. This is a nesting limit, not a total-expression-length limit: sequential expressions can exceed 64 factors. Failed calls leave the output unchanged and subsequent calls start with a fresh budget. Overflowing a bound or running out of steps returns a status rather than broadening the sandbox guarantee. No Rust type checker, ownership/borrowing, strings, crates, I/O or general Rust compatibility is offered. Invalid input can be reported by the host without killing the host process; the fixed budgets are not a security isolation boundary.
